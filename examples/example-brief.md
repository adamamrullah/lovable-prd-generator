# Example brief: community booking app

> I want a Lovable web app for a neighborhood language exchange. Members can create profiles, post weekly meetups, RSVP, and message organizers. We will run a private pilot with 30 people in one city. Make it mobile-first, English initially, no payments. I want an MVP PRD, with phased build prompts. Use reasonable defaults for anything missing.

Expected response behavior:
- Clearly identify private pilot as confirmed; don't add payments, native app, or public marketplace features.
- Challenge assumptions about moderation, organizer workloads, RSVPs and privacy of member profiles.
- Define auth, organizer role, event ownership, RSVP states/capacity, cancellation/no-show behavior and account deletion.
- Describe a complete RSVP workflow and how to validate it in a pilot.
- Give Lovable one implementable milestone at a time and require a real end-to-end test before expansion.
- Distinguish assumed defaults from confirmed choices.
